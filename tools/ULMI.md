# ULMI v0.1.0 — opt-in preview metadata
Default NONE: no extra metadata row, no source query, no image copy, existing direct redirect unchanged. Modes SNAPSHOT (permanent captured values, image URL only unless separately authorized archive), LIVE-SYNC (last known valid metadata, refresh only on authorized maintenance), CUSTOM (explicit approved metadata), PASSTHROUGH (reserved; true HTTP redirect unavailable on current static host; refuse rather than silently downgrade).
Private GLAIR PreviewPolicies and PreviewMetadata govern scopes and records. SMCC social-ready requests default LIVE-SYNC / PRE-PUBLISH+DAILY; ordinary requests default NONE. Explicit alias mode wins. Do not publish private sheet IDs, project labels, raw source HTML, metadata manifests, or audit records.
Capture: retrieve exact approved public source HTML/head with a network fetcher that validates public HTTPS, DNS and each redirect, no credentials/cookies, bounded timeout and max 512 KiB HTML; no arbitrary client URL input, no scripts, no private endpoints. Do not infer meta tags from article prose. For authorized third-party pages respect access restrictions. Run python tools/ulmi.py capture HEAD.html FINAL_PUBLIC_URL PRIVATE_METADATA.json. Resolve relative images using final source URL; metadata cap 8192 bytes, known tag allowlist, HTML-escape all values. Missing title is a blocker. Source OG URL recorded separately from canonical policy; ALIAS default for attribution; DESTINATION explicit opt-in may cause preview clients to canonicalize away the short link. Never modify destination binding. Images remain on original origin; same-URL image changes may require platform cache refresh. Frozen image bytes require separate rights and archive approval.
Issuance: use tools/stage_alias.py with --metadata-mode SNAPSHOT|LIVE-SYNC|CUSTOM --metadata PRIVATE_METADATA.json [--canonical ALIAS|DESTINATION]. Preserve original NONE invocation. Publish only redirect page and links.json atomically; record metadata in private registry after verification, not private manifest in GitHub. Verify preview from canonical uppercase short URL; social platform caches may retain old previews and may bypass tracked alias. Do not claim platform acceptance without actual crawler/composer verification.
Refresh: eligible ACTIVE LIVE-SYNC only, pre-publish and due schedule. Construct private record JSON with code_exact, mode, status, bound_destination, source_url, canonical_policy, metadata (object), metadata_sha256. Re-read GLAIR master, ULAS mirror and GitHub links.json; validate unchanged mapping. Capture fresh tags, then python tools/refresh_preview.py CURRENT_LINKS_JSON PRIVATE_RECORD_JSON NEW_METADATA_JSON NEW_OUTPUT_DIR. Unchanged hash => no commit; missing prior critical fields => retain last good and flag. On real change stage just canonical uppercase index.html; guarded commit/ref, re-read page, then update private metadata row, hash, captured_utc, next_due_utc, commit and audit. No alias allocation, DNS, analytics, or publishing posts. Snapshot and custom never automatically refreshed. Bound periodic run to 20 due records, one fetch per unique source per run, skip NONE, backoff on failure, no per-click retrieval. No-op if zero eligible. Scheduler activation and first live social preview acceptance separate from source/fixture tests.
Case normalization: lowercase links.json keys, uppercase printed canonical code, JS 404 fallback lowercases incoming code. Browser fallback requires JS; social crawlers should receive exact uppercase direct page URL.
